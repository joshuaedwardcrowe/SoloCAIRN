# Skills in SoloCAIRN

These were standalone roles in CAIRN, each owning their own artifacts. SoloCAIRN keeps the domain knowledge — how to run a discovery interview, how to think about mobile edge cases, how AI actually helps QA — but drops the standalone ownership, because there usually isn't a dedicated person to own it.

Instead: the two SoloCAIRN roles, [Maintainer](../roles/maintainer.md) and [Contributor](../roles/contributor.md), each draw on whichever skill fits the work in front of them right now. A Maintainer doing Discovery reads [Business Analysis](business-analyst.md) for interview technique. A Contributor building the mobile piece of a story reads [Mobile Development](mobile-dev.md) for platform-specific patterns. The skill still tells you *how* to do the work well; the role tells you *who's responsible* and *what artifact it becomes*.

## Skills not covered

Same as CAIRN: if your work needs DevOps, data engineering, security, or anything else not listed, it fits the same way — read for the practice, apply it as whichever role (Maintainer or Contributor) you're acting as in that moment. Write a new skill guide if you want one; copy the shape of an existing one.
